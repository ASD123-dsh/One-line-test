## 主要功能

- **19 种协议（当前源码）**：协议元数据集中注册，可在界面中切换。
- **状态与运行数据配置**：支持状态位、电流、霍尔计数、SOC、电压档位及协议专用字段。
- **场景预设**：提供正常运行、能量回收和故障场景；具体字段以对应协议规格书为准。
- **发送方式**：支持单帧、循环发送和自定义包组循环。
- **发送监控**：用有界表格显示发送时间、软件写入结果和十六进制帧。
- **界面浏览（本地测试版）**：协议下拉支持名称搜索，参数按页滚动，预设可浏览但不可编辑。
- **字节预览（本地测试版）**：按行显示字节与说明，支持复制整帧，并保留原始文本视图。
- **后台写入与统计**：界面生成最新帧快照，工作线程串行写入；缓冲积压时限流，
  显示写入计数、周期及待发字节，避免慢串口堵塞界面。
- **配置与诊断**：右上角统一“配置 / 诊断”菜单，支持配置导入导出、可选本机
  记忆和脱敏诊断。记忆默认关闭，导入不自动连接或开始发送。
- **帧输入校验**：统一校验帧长度、字节类型及 `0-255` 范围，避免非法自定义帧进入发送流程。
- **手动检测更新**：同一“配置 / 诊断”菜单提供“检测更新”和“扫码反馈”；发现新版自动下载，
  完整性校验后由用户确认升级并重启。

## 支持协议

当前源码注册表包含以下 19 种协议：

1. 瑞轮协议
2. FZ-sif 协议
3. 新日协议
4. 杭州安显协议
5. SXSY一线通协议
6. 常州新思维协议
7. 无锡一格 Y67 协议
8. 无锡台铃 Y34B 协议
9. 无锡台铃 Y34F 协议
10. 神州行协议
11. 雅迪协议
12. 优仪宝一线通协议
13. 精显一线通协议
14. 东威 GTXH 协议
15. 芯驰 BMS 协议
16. 绿源 BMS 一线通协议
17. 一线通--锂电池 BMS
18. 电池单线通讯协议
19. 锂神单线BMS

协议名称、帧长度、校验方式、发送方式、发送周期约束及帧生成入口统一维护在
`protocol/definitions.py`。新增协议时请按
[新增协议开发指南](docs/adding_protocol.md) 完成规格书核对、注册、实现和测试，不要继续在界面层堆叠协议分支。

“锂神单线BMS”提供 SOC、总电压和电池温度三项配置，生成六字节累加校验帧。
Byte1/Byte5 固定为 `00`，温度使用有符号八位补码，例如 -10℃ 编码为 `F6`。
新协议默认 `1000ms`，按用户选择保留 `10～5000ms` 测试范围；规格建议 `1000～2000ms`，
偏离建议周期不代表单线物理层或转码平台能够稳定处理。已有协议的全局默认 `500ms` 不变。

## 安装

### 环境要求

- Windows 10/11
- 已验证开发基线为 Python 3.11.9 x64；其他 Python 环境尚未验证
- 与目标设备电气特性匹配的串口转换/转码硬件

### 安装步骤

```powershell
git clone https://github.com/ASD123-dsh/One-line-test.git
cd One-line-test
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-lock.txt
```

运行时依赖包括：

- `PyQt5`：桌面界面
- `pyserial`：串口通信
- `rsa`：授权码相关功能

## 使用

```powershell
python main.py
```

基本流程：

1. 按目标规格书和硬件说明连接串口转换/转码设备，并确认电平、共地和信号方向。
2. 在界面中选择串口和波特率，然后连接。
3. 选择与目标仪表/BMS 一致的协议。
4. 选择场景或手动设置状态字段，核对当前帧预览。
5. 使用单帧、循环发送或包组循环发送。

普通“循环发送”会在每个发送周期读取当前配置：“数据自定义”中的字段修改、
预设场景切换，以及“全部自定义”中已应用的帧修改，均从下一帧生效，无需停发
重启。自动生成帧会重新计算校验，带流水号的协议每个发送周期递增；预览和
启动校验不消耗流水号。参数或帧数据无效时自动停发，并在发送历史中显示原因。
“包组循环”继续按已配置的帧列表轮流发送，循环期间主界面的字段修改不覆盖包组。

发送时最多一份后台在途任务。慢写期间暂缓生成下一帧，不提前消耗流水号；驱动
缓冲积压时仅保留一个待重试帧，并保持包组顺序。已经提交给驱动的在途字节不能
撤回，动态修改从下一份尚未提交的快照起生效。持续积压约 3 秒会停止循环并提示。
统计中的周期是软件写入调用间隔，不是单线侧波形的硬件实测值。

> 当前源码注册表的 19 种协议，主机侧 `send_mode` 均为
> `uart`。程序在这一契约下生成字节帧并写入串口；规格书中的单线脉宽、
> 位序、电压、电平和引脚要求，不能仅凭 Python 单元测试证明。不要在未确认
> 转码板、固件和实际接线的情况下，将普通 USB-TTL 串口直接视为目标单线总线。
> `Tosc` 也不会改变普通 UART 帧本身。

SXSY 模式生成规格书定义的 12 字节应用层帧。同步、单线高低电平宽度及位序等
物理层行为仍由接码转码平台负责，PC 端不会把载荷擅自扩展为 24 字节。规格书
图中“重复的数据 8bit”的含义仍需硬件确认；当前参考驱动按实际接收长度逐字节
转发。规格书建议约 `1s` 或更长的发送间隔，软件保留全局默认 `500ms` 及手动
调整能力，实际使用时应以硬件验证为准。

电池单线通讯协议的 BYTE1 数据头固定保持 `0x00`。为便于区分累加和与异或
校验，仅 BYTE3、BYTE4、BYTE5 的测试默认值设为 `0x01`，BYTE2 仍为 SOC，
BYTE6 仍为前五字节的 8 位累加和。例如 SOC 为 `80%` 时生成
`00 50 01 01 01 53`，累加和为 `0x53`，异或为 `0x51`；SOC 在 `0-100%` 时
两者始终不同。规格书中 BYTE3、BYTE4、BYTE5 原值为 `0x00`，
需要严格按规格书发送时，可在“全部自定义”中将它们改回 `0x00` 并重新计算
累加校验。已手动配置的自定义帧和已有包组不会自动替换这些字节。

循环发送间隔支持 `10-5000ms`，启动默认值仍为 `500ms`。使用低于 `500ms`
的周期前，应确认串口传输时间和转码平台的接收、缓存及转发能力；PC 端 Qt
定时器不是硬实时定时源，实际周期可能受系统调度影响。若转码固件没有帧队列，
新数据还可能覆盖尚未转发完成的上一帧。`10ms` 只是软件可选下限，不代表硬件
能够稳定达到该周期；默认 `9600bps/8N1` 下，10 字节及以上帧的理论发送时间已
不短于约 `10.4ms`，使用前应结合实际波特率、帧长和转码板能力验证。

## 架构

```text
One-line-test/
├── main.py                         # 程序入口与全局异常记录
├── app_paths.py                    # 开发环境/打包环境资源路径
├── gui/
│   ├── main_window.py              # 主窗口协调及发送控制
│   ├── protocol_pages/             # 按协议组织的配置页与状态绑定
│   ├── settings_panel.py           # 配置、诊断与恢复指引入口
│   ├── protocol_ui_registry.py     # 协议切换、预设及状态读写入口
│   ├── frame_config_dialog.py      # 单帧配置
│   └── packet_sequence_dialog.py   # 包组配置及导入导出
├── protocol/
│   ├── definitions.py              # 不可变协议元数据注册表
│   ├── models.py                   # ProtocolConfig、StatusBits 数据模型
│   ├── frame_utils.py              # 帧长度和字节范围公共校验
│   ├── codecs/                     # 各协议帧编码及流水号实现
│   ├── validation.py               # 参数校验
│   ├── descriptions.py             # 不可变字节说明
│   ├── presets.py                  # 预设场景
│   └── protocol_handler.py         # 保持旧接口的公共门面与共享编码辅助
├── serial_comm/
│   ├── serial_manager.py           # 串口连接、帧快照调度与结果处理
│   ├── send_worker.py              # 单一在途任务的后台写入线程
│   └── timing.py                   # 线速估算和写入统计
├── licensing/                      # 本地授权校验
├── tools/                          # 源码检查、发布归档；激活码生成工具仅本地私有
├── tests/                          # 单元测试和无界面 GUI 测试
├── docs/
│   └── adding_protocol.md          # 新增协议开发指南
├── PDF/                            # 本地协议规格书，默认不纳入 Git
└── 接码转码平台驱动源码/            # 转码平台相关 C 源码
```

核心职责如下：

- `definitions.py` 只描述协议元数据和分发入口，不实现字节编码。
- `models.py` 保存协议层与界面层共享的数据，不依赖 Qt 控件。
- `protocol_handler.py` 保留原导出入口；发送帧与预览帧统一通过注册表分发到独立组件。
- `protocol_ui_registry.py` 维护协议到界面处理方法的映射，减少主窗口中的重复分支。
- `frame_utils.py` 为单帧配置、包组配置和串口发送提供同一套帧数据校验。
- `serial_manager.py` 负责传输，不解释协议字段。

## 规格书与验证

本地 `PDF/` 目录用于保存厂商协议规格书。该目录已在 `.gitignore` 中忽略，
因此从远程仓库克隆后不一定存在。实现或修改协议前，应先核对对应版本的规格书，
至少记录以下内容：

- 帧长度、固定字节和字段字节序
- 位定义、物理量单位、精度、符号和合法范围
- 校验算法及覆盖范围
- 序号/加密字段，以及预览是否允许消耗序号
- 发送周期、位序和波形要求

软件测试可验证帧编码、参数边界、校验和、注册表完整性及界面映射，但不能替代
转码固件编译、示波器波形检查和目标仪表/BMS 联调。
