## 分模块实现

### 1. 后台串口写入和有界积压

- `SerialManager()` 默认保持同步返回契约。主窗口显式使用
  `SerialManager(background_send=True)`：返回成功表示快照已接受，真实写入结果
  仍通过原 `data_sent/send_error` 信号报告。
- UI 线程调用原帧提供器，提交不可变字节快照；工作线程只执行 I/O，不读取控件，
  不操作界面定时器。普通循环仍支持动态编辑，包组仍使用固定帧。
- 同时最多一份后台任务。慢写期间跳过调度、不生成下一帧、不提前消耗流水号。
  驱动待发字节超过两帧时仅保留一个待重试快照，不追加无界队列，包组顺序不丢失；
  已提交驱动的字节无法撤回，新数据从下一份尚未提交的快照起生效。
- 持续积压约 3 秒停止循环并提示；短时压力只作非阻塞、限频告警。
  按实际波特率和 8N1 帧长估算线速，低于理论耗时会警告，但不偷偷修改用户设置。
- 断开请求等待当前帧结果；后台忙时拒绝重新连接，防止旧完成回调关闭新连接。
  关闭窗口等待线程退出，超时保留窗口和串口，不强杀线程。
- 默认仍为 500ms，软件可选范围仍为 10～5000ms；直接 BREAK 模拟波形的兼容模式
  仍保持原 500ms 下限。全部 18 种协议的主机侧 UART 契约没有改变。
- 统计为写入驱动确认的帧数、软件写入调用周期、待发字节及延后次数，最多约 10Hz
  刷新显示；不是物理线路发送完成确认，也不是转码板单线侧波形实测。

### 4. 固定环境和 CI

- 固定现有已验证的 Windows x64 / Python 3.11.9 基线，运行依赖使用
  `requirements-lock.txt`，明确要求编译后才使用 `requirements-build.txt`。
  本次没有安装或升级依赖，也没有执行 PyInstaller。
- 本地统一入口 `python -B tools/check_project.py` 解析语法、检查冲突并运行回归；
  设置 `PYTHONDONTWRITEBYTECODE=1`，不生成字节码、EXE 或发布包。
- 新增 Windows 源码检查工作流，仅 `contents: read` 权限，不编译、不提交、
  不上传附件或自动发布。文件未推送，因此没有线上 Actions 成功记录。
- Action 配置参考官方 [setup-python](https://github.com/actions/setup-python) 和
  [checkout](https://github.com/actions/checkout)。线程职责参考
  [Qt 5.15 Threads and QObjects](https://doc.qt.io/archives/qt-5.15/threads-qobject.html)。
  固定依赖基线不代表承诺位级可复现，也不代表依赖永不需要后续安全升级。

### 5. 只读中断事务识别

- 普通打包版启动只检查当前安装目录内的专属锁及对应事务，核对软件身份、随机
  标识、规范路径、记录大小、状态、文件清单和摘要格式，不扫描其他应用目录。
- 正常升级启动握手期间跳过检查，避免把仍在执行的本次事务误判为中断。
- 检测到记录后提供恢复指引并阻止重复创建升级安装；损坏、链接或身份不明的记录
  保留现场，只提示联系作者。未自动回滚、删除锁、清理备份或跟随外部事务路径。
- 普通失败回滚、成功清理的既有更新代码未改写。此能力不是断电自动恢复保证，
  也不能修复 Python 运行库已严重损坏而根本无法启动的安装；此时应使用官方完整包
  解压到新的独立目录并保留原现场。

### 6. 配置、日志与脱敏诊断

- 右上角新增独立“配置 / 诊断”按钮；原问号菜单仍只有检测更新、扫码反馈两项。
  发送区新增写入统计行，其他主要布局不重设计。
- 本机记忆默认关闭，首次启动仍为 500ms。用户开启后才保存参数；导入配置前必须
  停发并断开串口，导入或恢复都不会自动连接、自动发送。
- JSON 配置含软件身份和 schema，限制 1MiB，拒绝未知字段、非法数值/类型、
  非有限值、无效帧长和包组；先校验后原子保存，不覆盖式清空整个目录。
- 配置与滚动日志在 `%LOCALAPPDATA%/ad-meter-single-wire-tool/`，
  不放进混放安装目录。日志上限约 512KiB × 3；异常日志也移至该专属目录。
- 诊断导出仅包含协议、参数和统计白名单，不导出串口身份、机器标识、授权文件、
  客户路径、原始日志或其他应用文件。
