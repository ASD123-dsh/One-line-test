## 用户反馈与实现范围

用户反馈一线通工具在前台时使用 Shift 不能切换中英文，切到其他应用后可切换，
截图中输入 `rui` 无搜索结果；用户选择不新增依赖，集中维护协议全拼和首字母索引。

本次只改搜索相关界面和回归，不编译、不打包、不改版本号，不提交、不推送或发布。

## 排查证据及边界

现有源码未发现全局 Shift 钩子或修改系统输入法开关的代码。原搜索层使用 `Qt.Popup`，
本机 Qt 检查确认其进入 `QApplication.activePopupWidget()`；输入框本身的
`WA_InputMethodEnabled` 已为真，因此不能把问题简单归因于未打开该属性。
原 `rui` 查询为空，是仅按中文名称包含关系匹配的确定性问题。

Qt 5.15.2 的 Windows 平台层根据当前焦点对象更新窗口 IME 关联，非输入控件可能
禁用当前窗口的输入法上下文；菜单式弹层与实际编辑焦点组合存在兼容风险。
此结论参考 [Qt 官方 Windows 输入法实现](https://github.com/qt/qtbase/blob/v5.15.2/src/plugins/platforms/windows/qwindowsinputcontext.cpp)，
不能据此宣称已在真实微软/搜狗输入法上复现或完全解决用户的前台 Shift 问题。

本轮先消除搜索层的焦点/抓取风险，让实际编辑框通过 Qt 原有输入法通道接收合成文本，
不强制所有数字控件或按钮打开中文输入，不调用 Windows 全局输入法 API，也不修改
系统快捷键设置。真实输入法 Shift 切换及候选窗交互需要后续 Windows 实机复测。

## 关键修改

- 搜索层改为可激活的无边框 `Qt.Tool`，焦点明确交给编辑框，不使用菜单式键盘抓取。
- 使用标准 `QLineEdit` 输入法支持，并保留 Shift、Ctrl、Alt、Win+空格等按键交给 Qt/系统。
- 只在浮层可见时安装 Qt 应用内事件过滤器，处理外部点击、普通 Esc 和上下导航，收起即移除。
- 候选合成期间的回车、Esc、上下键不作为协议操作；输入法短暂激活其他窗口时不立刻隐藏浮层。
- 新增只读集中索引 `gui/protocol_search.py`，覆盖 19 个现有协议的全拼及首字母。
- 保留中文名称和型号搜索，忽略大小写、全半角及常见分隔符，绿源兼容 `lvyuan`、`lüyuan`、`luyuan`。
- 输入只过滤已有结果，按键导航只移动高亮；明确选择后才发送原协议切换信号。
- 新协议扩展指南要求补充一条拼音索引，回归检查索引与协议注册表一一覆盖。

示例：`rui` / `ruilun` / `rl` 找瑞轮，`xinri` / `xr` 找新日，`lishen` / `ls` 找锂神，
`Y34B` / `Y67` 等原型号仍可直接搜索。搜索别名不是新的协议名称或编码入口。

IME 合成与提交分开处理依据 [Qt 输入法事件说明](https://doc.qt.io/archives/qt-5.15/qinputmethodevent.html)。
测试使用 `QInputMethodQueryEvent(Qt.ImEnabled)` 检查实际可输入状态；直接调用
`QLineEdit.inputMethodQuery(Qt.ImEnabled)` 在当前 Qt 5.15.2 返回 `None`，不等于 IME 被禁用。

- 验证 Shift 等模式键不被应用过滤器吞掉，候选阶段 Esc/上下/回车不触发协议选择。
- 覆盖外部点击、重复点击箭头、Esc、重开、主窗口隐藏和无结果回车。
- 真实主窗口配合假发送状态，确认拼音搜索及取消不改变配置、不停止循环，明确选择才停止旧循环。
- 106 个 Python 文件只读语法检查、400 项全量回归通过；没有编译、打包或执行真实串口。

这些是 Qt 控件事件和离屏回归证据，不是原生 Windows Shift 切换、真实 IME 候选框、
物理串口或完整软件升级的实测证明。验收时应在新版 EXE 的搜索框分别测试中英文
Shift 切换、中文候选确认/取消、`rui` 和 `rl` 搜索；若前台问题仍存在，需要继续定位，
不能将本轮测试报告作为“已彻底修好”的依据。
