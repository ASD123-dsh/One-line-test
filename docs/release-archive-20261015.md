## 自动归档规则

后续由本项目开发流程完成正式发布时，归档与清理是结束任务前的固定步骤，不需
用户再单独提醒。不是客户软件的新功能，也不创建定时监控。

1. 用户确认功能正常并授权发布后，按原流程合并、发布并核验线上附件。
2. 保存真实发布记录，调用 `tools/archive_release.py` 归档；命令见
   [发布说明](releasing.md#发布成功后的自动归档)。
3. 校验仓库、公开状态、版本标签、合并提交、四个附件的大小和 SHA-256，核对
   校验文件正文；复制完成后再次校验，再清理已归档的重复生成文件。
4. 同版本已有文件内容相同则只复核、不改写；内容不同立即停止，不覆盖历史版。
   中断后可补齐缺少的文件。发布未成功时不能以归档名义删除原包。
5. 保留历史正式包、必要升级测试输入及用户文件；按项目规则清理本次自有的构建
   中间目录、已完成测试副本和缓存，不扫描删除未知目录。

工具不联网、不编译、不提交、不发布。调用方负责先完成真实 GitHub 核验；本地
记录检查不能替代线上确认。再次核验 V1.58.2 时，使用正式归档中的发布记录和
打包快照作为输入，因为原生成记录副本已按规则清理。
