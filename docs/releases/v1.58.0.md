# V1.58.0：手动更新功能验证版

本版本用于从已分发的 V1.57.0 验证 GitHub Releases 检测、自动下载、完整性校验、
用户确认升级和重启流程。相对本地 V1.57.0，仅推进软件版本号；不修改协议编码、
串口发送接口、发送间隔范围、扫码反馈和授权逻辑。

## 功能

- 右上角 `?` 提供“检测更新”和“扫码反馈”。
- 用户主动检测 GitHub 最新稳定版本，发现新版本后自动下载完整 ZIP。
- 下载后校验大小、GitHub SHA-256、文件清单和逐文件摘要。
- 用户确认后，独立更新器准备就绪，主程序停止发送并关闭串口，再替换和重启。
- 保留旧版程序备份和程序目录中的用户导出文件；授权数据位置保持不变。
- 保留普通循环发送时动态读取当前配置的优化，包组循环仍按已配置帧列表发送。

## 用 V1.57.0 测试

1. 保留完整的 `AD仪表一线通协议测试工具` 文件夹及 `_internal`，放在有写权限的目录。
2. 启动 V1.57.0，点击 `? → 检测更新`。
3. 检测到 V1.58.0 后应自动下载并校验，不需要再次点击下载。
4. 保存需要保留的包组，关闭同一目录中的其他工具实例。
5. 点击“升级并重启”并确认，等待新版启动；窗口应显示软件版本 V1.58.0。
6. 再次检测更新，应提示已是最新版本；检查原有协议和扫码反馈功能。

完整附件：`AD-OneLine-v1.58.0-windows-x64.zip`。

首次安装或不支持自动更新的旧版用户，需要手动解压并使用完整程序文件夹，不能只
下载主 EXE。网络环境需要能访问 GitHub API 和 Releases 附件域名。

## 验证与边界

发布前运行源码回归、发布包完整性检查、真实 EXE 启动和隔离安装测试。
验证记录随本地发布产物保存。真实硬件串口功能与用户所在网络环境仍需实测，
不能以单元测试或隐藏启动检查代替。

本次源码提交同时记录此前已在本地 V1.57.0 中完成、但尚未提交到仓库的更新模块和
动态循环发送功能；PDF、参考硬件驱动、私钥、授权文件和本地二进制不进入源码提交。
