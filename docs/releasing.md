# 软件发布与手动升级

## 用户侧流程

右上角 `?` 菜单提供两项：

- **检测更新**：用户主动检测 GitHub 最新稳定版。发现更高版本后自动下载完整
  ZIP，显示进度并验证下载大小、GitHub SHA-256 摘要、包内清单和逐文件摘要。
  校验通过后，用户点击“升级并重启”并确认，才进入安装。
- **扫码反馈**：继续打开原有作者联系二维码和授权有效期页面。

软件启动时不会自动检测，不需要用户提供 GitHub 账号或令牌。检测和下载在后台
执行，不阻塞界面。关闭下载窗口会先取消任务并等待后台结束；网络失败或下载损坏
不影响现有程序。

升级确认框会提示先导出需要保存的包组。更新器准备好同盘候选目录后，原程序才
停止循环发送、关闭串口并退出，随后独立更新器替换程序并重新启动。

## 版本和附件约定

- 软件版本统一修改 `app_info.py` 中的 `APP_VERSION`，采用 `主版本.次版本.修订`
  三段数字，例如 `1.57.0`、`1.58.0`。
- `PROTOCOL_VERSION` 是原有协议说明版本，新增软件功能无需改变协议编码。
- 发布仓库固定为 `ASD123-dsh/One-line-test`，客户端只读取稳定 Release。
- 发行标签使用 `v` 加软件版本，例如 `v1.58.1`。
- 完整附件名为 `AD-OneLine-v1.58.1-windows-x64.zip`，由发布工具自动生成。
- 包内必须包括主 EXE、完整 `_internal`、独立 `updater.exe` 和
  `update-manifest.json`。客户端不接受单个 EXE、RAR 或 GitHub 自动生成的源码 ZIP。

## 作者发布步骤

1. 更新 `app_info.py` 的 `APP_VERSION`，保持版本递增。
2. 在项目根目录运行回归测试：

   ```powershell
   python -m unittest discover -s tests -v
   ```

3. 在有 PyInstaller 的 Windows 开发环境中运行：

   ```powershell
   python tools/build_release.py
   ```

   首次开发环境缺少打包工具时可安装：`python -m pip install PyInstaller`。
   终端用户不需要安装 Python 或这些开发工具。

   发布工具分别打包独立更新器和主程序，在新的
   `dist/releases/v1.58.1/` 目录输出完整程序文件夹、ZIP 和 `.zip.sha256` 校验文件。
   它不会自动上传 GitHub，也不会覆盖原来的 `dist` 正式程序或已有发布目录。
   如需重复构建同一版本，使用 `--output` 指定另一个新的目录。

4. 从新目录启动程序，确认功能和版本号。提交并推送对应源码后，在 GitHub
   Releases 创建同版本的稳定 Release，选择对应代码提交并填写更新说明。
5. 上传发布工具生成的完整 ZIP 和校验文件，将该 Release 标记为最新版本。
   GitHub 会计算附件摘要，客户端使用 API 返回的 SHA-256 校验下载内容。

发布包必须由本工具构建；只把主 EXE 上传到 Releases 不足以提供自动升级。
现有较早的 `v1.0.0` 单 EXE 发行版不会导致客户端降级。

## 首次启用的迁移

之前已分发的 V1.56 没有检测更新功能，需要用户先手动下载并使用一次包含更新器的
完整新版本。以后再发布更高版本，用户即可通过 `? → 检测更新` 完成下载和升级。

建议将整个 `AD仪表一线通协议测试工具` 文件夹放在用户有写权限的独立目录。
保留这个程序文件夹名称，不要只复制 EXE 或把所有文件直接散放到桌面、文档目录。
源码运行时可以检测和下载，但不会自动覆盖 Python 解释器或源码目录。

## 备份、数据和失败恢复

- 激活文件仍位于原有 `%APPDATA%/AD仪表一线通协议测试工具/`，更新器不访问或删除
  此路径。授权逻辑和有效期规则没有变化。
- 原程序目录内的用户导出文件会复制到新目录。若文件与新版程序同名，以新版程序
  为准；原用户文件仍保留在旧版备份中。内存中的未导出包组需在升级前自行保存。
- 原程序整体保存在旁边的 `AD仪表一线通协议测试工具.backup-时间-随机编号`
  文件夹中，不会自动删除。
- 安装在目标同一磁盘准备候选目录，支持下载暂存在 C 盘而程序位于 D 盘的情况。
- 目录替换失败或无法创建新版进程时会尝试恢复旧版；如果新版能够启动但运行逻辑
  存在问题，可关闭程序后将新版目录移走，再把备份目录改回原名，恢复旧版。
- 更新器状态保存在系统临时目录的 `sifexe-update-*` 文件夹内。成功后清理大体积
  下载和解压副本，更新器自身和状态记录可在所有更新进程退出后再手动清理。
- 无写权限、程序目录被占用、下载校验不通过等情况会停止升级并提示原因。
- 同一程序目录如果打开了多个工具窗口，请先关闭其他窗口后再升级。
- Windows 目录改名遇到访问拒绝或共享占用时，最多尝试 80 次，间隔 250ms；
  其他错误立即停止，不自动删除或覆盖冲突目录。备份恢复也使用相同的有限重试。
- 失败后的 `handoff.json` 保留失败阶段、原始 Windows 错误码、系统原因和完整异常链，
  便于区分临时文件占用、路径冲突和权限问题，不再只显示概括的失败提示。
- 安装动作由当前已安装版本的更新器执行。修复旧版更新器时，只发布一个新 ZIP
  不会改变旧版的安装逻辑；应先修复本地更新器并刷新对应清单，再重新测试升级。

## 验证范围

单元测试使用模拟网络和独占临时程序目录，覆盖版本判断、自动下载、取消竞态、
完整包和路径验证、真实目录改名事务、旧版回滚和 Windows 进程句柄验证。
正式发布前仍应使用两个不同版本的完整 Windows 发布包进行一次实际升级验证。

## 实现文件与职责

| 文件 | 本次更新职责 |
| --- | --- |
| `app_info.py` | 集中软件版本、仓库和完整包约定 |
| `main.py` | 使用集中软件版本 |
| `gui/main_window.py` | 问号两项菜单和升级前关闭发送流程 |
| `gui/update_dialog.py` | 后台检测、自动下载、进度、取消和用户升级确认 |
| `updating/__init__.py` | 独立更新模块入口 |
| `updating/releases.py` | 发行版查询、数字版本比较、HTTPS 下载与摘要校验 |
| `updating/package.py` | 完整包清单、逐文件校验、安全解压和暂存目录管理 |
| `updating/controller.py` | 下载准备、独立更新器启动与握手 |
| `updating/installer.py` | 同盘安装事务、用户文件保留、进程等待和旧版回滚 |
| `tools/update_installer.py` | 独立更新器打包入口 |
| `tools/build_release.py` | 主程序、更新器、完整 ZIP 和校验文件发布打包 |
| `tests/test_updates.py` | 下载、路径、完整包、回滚及 Windows 进程验证 |
| `tests/test_update_dialog.py` | 菜单、自动下载、确认、取消竞态与握手验证 |
| `README.md` | 更新功能入口及发布说明链接 |
| `docs/releasing.md` | 完整发布、迁移、备份恢复和验证说明 |

接口依据：[GitHub Releases 官方 API](https://docs.github.com/en/rest/releases/releases)。
独立进程的打包环境重置依据：[PyInstaller 应用重启说明](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#using-sys-executable-to-spawn-subprocesses-that-outlive-the-application-process-implementing-application-restart)。
