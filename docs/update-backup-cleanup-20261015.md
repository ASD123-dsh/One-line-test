# 升级成功后的旧版备份自动清理

日期：2026-10-15。当前为本地源码修改，尚未打包、提交或发布，不改变线上 V1.58.1 附件。

本文件记录最初的整目录清理方案。后续根据用户要求，已改为专属运行库和按清单
逐文件事务，不再搬动或备份整个安装目录；最终实现以
[混放目录逐文件升级说明](update-managed-files-20261015.md) 为准。

## 需求及最小修改范围

用户希望成功升级后不再积累同级 `.backup-*` 文件夹，升级失败时仍能恢复旧版。
沿用原 PyQt5、独立更新器、完整 ZIP 和清单约定，不改协议帧、串口接口、授权规则、
菜单、软件版本号或现有已发布程序。没有引入第三方依赖。

旧逻辑只检查进程能否创建，不能识别启动后立即退出、界面构造失败或一直未就绪。
因此不能直接在 `Popen` 返回时删除备份。

## 升级事务

1. 校验下载与候选目录，复制用户文件，准备同盘安装。
2. 原程序退出后，将旧目录改名为本次唯一备份，再替换候选目录。
3. 新进程继承一个私有启动请求路径。请求存放于本次独占暂存目录，绑定随机标识、
   软件身份、目标版本和主 EXE 绝对路径；新界面进入事件循环后写入进程号及就绪确认。
4. 更新器等待确认，最长 60 秒；确认后观察进程持续运行 5 秒。正常的授权界面也是
   可用的启动界面，不改变授权流程。普通启动没有请求时不会访问握手文件。
5. 安装、启动或确认失败时，不进入成功清理分支。必要时仅停止本次启动的未就绪
   新进程，然后恢复并重启旧版；不能安全停止或恢复受阻时保留备份并报告精确路径。
6. 确认成功后，仅清理本次备份，既不遍历其他备份名，也不删除截图中的历史备份。

已有调用方式仍可使用：启动器和安装事务仅增加可选参数；任务、ZIP、清单和对外菜单
保持现有格式，旧版下载与更新接口不变。

## 删除保护

- 删除前解析绝对路径，备份必须是当前程序的同级普通目录，名称必须严格匹配本次
  计划。禁止当前程序、父目录、根目录、链接和联接点。
- 确认旧清单仍与安装前记录一致，当前版本确实高于旧版。
- 逐个确认原用户导出文件已在新目录中完整保留。缺失、改动或同名冲突时保留备份，
  防止删除用户文件的唯一副本；旧主程序等非运行库文件被改动时也不自动清理。
- 运行库目录仍按原规则管理，不迁移旧 `_internal` 内容；用户资料不要存入该目录。
- 删除遇到 Windows 错误码 5、32、33 时最多尝试 8 次，间隔 250ms。无法完成时
  保留未清理内容并记录警告，不再回滚已确认成功的新版，也不误报为升级失败。
- 成功后不再留长期降级备份；启动确认不能证明全部协议功能正常，正式发布仍需用户
  功能确认。稍后才发现的业务问题需重新下载旧版完整包。

日志继续位于本次 `sifexe-update-*` 暂存目录的 `handoff.json`：
`backup` 记录原备份路径，`backup_removed` 记录清理结果，`cleanup_warning` 记录异常。

## 旧版首次升级限制

安装由当前版本自带更新器执行。已分发的 V1.58.1 及更早版本没有本次清理逻辑，
首次升级到新功能版本时仍可能保留一次备份。此后由新版更新器执行的升级才会自动清理。
如果要在首次本地复测中验证清理，需使用独立测试副本内的新版更新器并更新完整性
清单；不能直接用旧更新器的结果证明新清理流程正常。此次不处理历史备份。
