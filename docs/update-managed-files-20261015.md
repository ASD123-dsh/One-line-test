# 混放目录的逐文件升级

日期：2026-10-15。V1.58.2 已编译并完成下面的软件验收；用户随后确认混放升级、
失败回滚和成功清理均测试正常，并授权合并 main 及正式发布。沿用已测试通过的
两个 ZIP，不重新编译；版本和迁移说明见 [V1.58.2 发布说明](releases/v1.58.2.md)。

## 用户确认的方案

用户要求同级混放其他应用和文件时，只更新、备份一线通工具自身文件，并保留失败
回滚及成功自动清理。用户已确认使用专属运行库目录方案；仍分发完整文件夹和 ZIP，
不改成单 EXE。不更改协议帧、串口接口、授权规则或 UI 布局。

## 文件归属与处理范围

| 路径 | 更新规则 |
| --- | --- |
| `AD仪表一线通协议测试工具.exe` | 按摘要替换，变化前备份 |
| `_ad_oneline_internal/` 中清单所列文件 | 仅替换变化文件、移除废弃自有文件；未知文件原位保留 |
| `ad-oneline-update-manifest.json` | 本工具专属清单，最后切换版本 |
| 旧共享 `_internal/` | 迁移时不改、不删、不复制、不备份 |
| 其他 EXE、其他应用目录、用户导出文件 | 原位保留，不参与备份、安装和回滚 |
| 旧 `update-manifest.json` | 身份确属旧一线通安装时备份并退役；专属清单存在时忽略其他应用的通用清单 |

程序目录名可任意，不再要求与工具名称相同；主 EXE 名、专属依赖目录和清单名仍
需保持完整。清单不能声明同级任意其他应用路径。新文件路径被未知文件占用，或
旧自有文件与安装清单摘要不符时，停止升级，不覆盖或猜测归属。

其他软件不要主动依赖本工具专属运行库。工具也不会识别并迁移其他软件的依赖。
如果旧安装缺少有效本工具清单，应完整手动安装一次，不能扫描混放目录来猜所有权。

## 事务与恢复

1. 校验下载包及目标身份。新事务只安装专属运行库包，旧共享布局仅作为迁移来源。
2. 独占创建 `.ad-oneline-update.lock`，准备同盘 `.ad-oneline-update-随机标识/`。
   `candidate/` 只存新工具文件，`backup/` 只存本次会变化且原先存在的自有文件。
   未变化文件不改写、不重复备份；不备份用户文档、其他应用或共享运行库。
3. 主程序正常退出后，记录每个文件改动，再逐个原子替换。主 EXE 和专属清单靠后
   切换，安装目录本身不重命名、不替换。文件替换完成后再次校验全部新版自有文件。
4. 新界面进入事件循环后，通过随机标识、目标版本、程序路径和进程号确认启动。
   最长等待 60 秒，确认后继续观察 5 秒并再次校验自有文件。
5. 替换、启动或确认失败时，仅恢复本次已尝试修改的自有文件，并移除本次新建的
   自有文件；其他应用和期间新导出的用户数据始终留在原位。必要时只停止本次
   启动的未就绪新进程，不结束其他应用进程。
6. 新版就绪后提交事务，按记录和摘要清理本次候选、最小备份及空工作目录，并释放
   自有锁。只删除空目录，不对安装目录或未知文件使用递归删除。

安装和恢复遇到 Windows 5/32/33 最多尝试 80 次，间隔 250ms；备份清理最多 8 次。
持续清理占用、事务目录中出现未知文件、备份被修改等情况只产生清理警告，保留
未清理内容，不误报升级失败。历史备份不扫描删除。

恢复失败或新进程不能安全停止时，保留最小备份、`transaction.json` 及锁，阻止
继续覆盖。错误提示给出备份位置，暂存 `handoff.json` 保留失败阶段和原系统原因。
备份只是恢复材料，不是可独立启动的旧版文件夹；人工恢复需依照事务记录把旧文件
放回原位置。不能直接运行最小备份中的主 EXE。

`handoff.json` 的 `backup_removed`、`cleanup_warning` 记录自动清理结果。清理成功
后不保留长期降级副本；后续业务问题需重新下载旧版完整发行包。
强制关机、断电或结束更新器留下的事务需要人工检查；本实现不宣称断电自动恢复。

## 发布格式与旧客户端

- 主包：`AD-OneLine-v<版本>-windows-x64-managed.zip`，专属目录和专属清单，
  新客户端优先选择，也是客户手动分发推荐包。
- 过渡包：`AD-OneLine-v<版本>-windows-x64.zip`，旧 `_internal` 与通用清单格式，
  供原独立目录旧客户端先升级到带新更新器的版本。版本、源码和功能与主包一致。
- 构建脚本生成一个独立更新器、两种主程序布局和四个附件（两个 ZIP、两个校验文件）。
  主包程序位于发布目录的工具文件夹；过渡程序只在临时构建目录中打包，输出目录
  不再额外保留 `legacy/` 可运行副本。
- 旧更新器不能因为下载新版本就提前改写自身。已混放的 V1.58.1 及更早版本首次
  迁移需手动完整解压主包，或在受控副本中更新安装器和清单。原独立目录可通过
  过渡包升级；旧安装器首次仍可能保留一次整目录备份。
- 安全模式发现专属附件有误时不会回退到共享运行库包。旧 Release 仍可检测和下载，
  但逐文件安装器拒绝将共享运行库包安装进混放目录。

仅用户明确要求打包时编译；用户确认功能测试通过后，按约定提交合并 main 并发布。
版本号未确定时先确认，不能用待发布源码覆盖线上 V1.58.1。

  包括原有协议、串口、授权和 UI 测试。

  自有 DLL 持续占用时回滚；备份占用释放后可清理，持续占用只记录警告。
- 启动握手保留真实独立 Python/Qt 子进程测试，生产 5 秒窗口有时钟模拟回归。
- 构建脚本先通过模拟 PyInstaller 产物验证两种布局及附件；用户随后明确要求打包，
  已使用 Python 3.11.9、PyInstaller 6.20.0 编译真实主包、过渡包和独立更新器。
- 从已发布 V1.58.1 主 EXE 提取实际旧更新模块，在开发 Python 中验证：旧客户端
  选择并解压校验合成过渡 ZIP，新客户端选择并解压校验合成 managed ZIP。
  这是模块级兼容测试，不是实际旧 EXE 升级新 EXE。
- 真实 EXE 受控副本测试：V1.58.1 旧共享布局由新版更新器迁移到 V1.58.2 专属布局，
  新版 GUI 确认并稳定运行，`backup_removed=true`，本次事务目录及锁均删除。
  备份只包含旧主 EXE 和旧自有清单，不备份共享依赖或混放内容。
- 真实 EXE 占用测试：Windows 拒绝主 EXE 替换，80 次重试后触发回滚，恢复
  V1.58.1 全部旧文件、移除新建专属依赖、释放锁并重新启动旧版。失败记录和最小
  备份留存。两个场景各有 186 个共享依赖及混放文件的摘要、修改时间、文件标识
  比较，全部不变。后台测试程序已按两个精确随机测试路径核对并关闭。
- 对主包和过渡包逐文件校验、重新解压 ZIP 并校验、校验图标与反馈图片；每种布局
  EXE 的 27 个项目模块及独立更新器的 8 个模块与当前源码字节码一致。
  两种主程序额外各离屏启动 5 秒，未生成异常日志。尚需用户真实桌面交互及串口
  硬件复测，不把离屏启动视为所有协议或硬件功能通过。
- 因为本次不发布，以上使用本地 ZIP 和真实更新器进行安装验收，未走线上检测及
  自动下载。旧 V1.58.1 原更新器不能安全迁移混放目录；本地入口特意调用候选包中
  的新版更新器，不能据此宣称旧线上更新器已支持混放。
- 上述本地验收阶段未提交、合并、推送或修改 GitHub Releases；用户确认正常后
